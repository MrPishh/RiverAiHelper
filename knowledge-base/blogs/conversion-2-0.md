Conversion 2.0 is now live. The system follows the original 180 day structure with no reset. Conversion resumes from Day 48 at a rate of 0.005333.

**Before converting, read this part first.**

Conversion 2.0 uses a new contract and a dynamic conversion curve. The actual conversion rate updates every block and may differ slightly from the expected baseline.

Always check the live rate and available capacity before confirming. Your final output is determined by the rate at execution, which reflects current participation.

This upgrade builds on the original framework and adds mechanisms that distribute activity through time, reduce short-interval pressure, and align output with longer participation.

### What remains the same

Two elements stay consistent with the original design.

-   180 day conversion window
-   30% maximum allocation from River Pts conversion

These parameters remain unchanged.

### What is upgraded in Conversion 2.0

Conversion follows the original structure with several upgraded components. These upgrades were informed by community feedback and aim to support more balanced participation.

-   Daily Conversion Cap
-   Per Conversion Limit
-   Dynamic Conversion Curve
-   Half Life Recovery
-   Output as Staked RIVER

The purpose is to spread activity more evenly, avoid concentration, and improve system behavior over time.

#### Daily Conversion Cap

20,000,000 River Pts per day. This avoids single day surges and spreads access across the full window.

#### Per Conversion Limit

1,000,000 River Pts per conversion. No single action can use an entire day of capacity. Splitting transactions does not increase total output.

#### Dynamic Conversion Curve

The previous linear structure did not respond to participation density. Conversion 2.0 uses an integral curve that adjusts continuously.

Dense participation compresses the marginal rate while lower activity moves toward the baseline defined by the original schedule.

#### Half Life Recovery

When activity slows, the curve moves toward the baseline through a continuous recovery function. This reduces timing advantages and avoids manual intervention.

#### Output becomes Staked RIVER

All conversion output becomes Staked RIVER. The system calculates a fixed base result from River Pts and then applies the selected duration, where longer durations receive a larger share within the same base amount.

This does not increase output. It reallocates the same amount toward longer epochs and aligns both voting power and yield with the selection.

Staked RIVER continues to earn River Pts and carries governance weight across epochs.

#### Operational calibration

As Conversion 2.0 operates, certain parameters such as daily capacity or per conversion limits may be calibrated. Any calibration follows the established public process and cannot be changed informally.

These steps reflect community discussion and preserve long term stability and user position safety.
